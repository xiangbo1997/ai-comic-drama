# MVP-1 基线测试指南

> **目的**：在 Phase 1 之前，先做 v1 vs MVP-1 双盲评分，确认方向正确再继续投入。
> **预计耗时**：4-6h（含 workflow 执行 + 评分）
> **依赖**：MVP-1 改动已落盘（见 `character-consistency-v2-implementation-log.md`）

---

## 1. 测试集准备

### 1.1 选 3-5 条代表性脚本

每条脚本满足：
- 主角清晰、有 1-2 张定妆图（写入 `Character.referenceImages` 或 `CharacterReferenceAsset`）
- 8-15 个分镜（不要太少看不出问题、也不要太多评分疲劳）
- 包含至少 1 次镜头切换（远→近 / 内景→外景 / 角度变化）

推荐三类剧本各选 1 条：
1. **单角色为主**（90% 镜头有同一主角）— 检验视频内身份保持
2. **双角色对话**（一半镜头有 2 个角色同框）— 检验多角色一致性
3. **多场景切换**（≥ 3 个不同环境）— 检验跨镜头连续性

### 1.2 准备运行环境

**v1 模式**（旧行为）：
```bash
# 在远端 .env.local 或部署环境中临时设置：
export ENABLE_VIDEO_XFADE=0
# 同时回滚 workflow-engine.ts 到 HEAD 版本（备份后再恢复）
git stash push app/src/services/agents/workflow-engine.ts app/src/types/ai.ts
pnpm build
```

**MVP-1 模式**（新行为）：
```bash
# 不设 ENABLE_VIDEO_XFADE（默认开）
unset ENABLE_VIDEO_XFADE
git stash pop  # 恢复 v2 改动
pnpm build
```

> **简化建议**：实际操作中可以**只跑 MVP-1**，把项目里已有的旧产出（如 Apr-May 之间生成的视频）作为 v1 基线。这样省去回滚的麻烦。

## 2. 双盲评分流程

### 2.1 准备评分表

每条脚本生成 2 个版本视频后，按下表收集 3 个评委的评分：

| 维度 | 1 分 | 3 分 | 5 分 | 权重 |
|------|------|------|------|------|
| **角色身份一致性**（主角在所有镜头是同一个人？） | 5+ 次明显漂移 | 偶尔有差异 | 全程一致 | 40% |
| **视频内帧间稳定**（同一镜头 5s 内角色不抖？） | 大幅抖动 | 轻微抖动 | 完全稳定 | 25% |
| **镜头切换连贯**（镜头边界是否硬切跳变？） | 每次切换都明显 | 部分镜头跳变 | 切换自然 | 25% |
| **整体观感**（你愿意把它发到朋友圈吗？） | 不可接受 | 凑合 | 真不错 | 10% |

加权综合分：`overall = 0.4*A + 0.25*B + 0.25*C + 0.1*D`

### 2.2 双盲保证

- 评委**不知道**哪个视频是 v1 / MVP-1
- 视频文件名只用 hash（`xxxx_v1.mp4` 改名为 `sample_a.mp4`，`xxxx_v2.mp4` 改名为 `sample_b.mp4`）
- 评分先独立写下、再汇总，避免相互影响

### 2.3 评分数据记录模板

| 脚本 | 评委 | A 身份 | B 帧间 | C 切换 | D 观感 | 加权 |
|------|------|--------|--------|--------|--------|------|
| 单角色 - v1 | 评委1 | | | | | |
| 单角色 - MVP-1 | 评委1 | | | | | |
| 双角色对话 - v1 | 评委2 | | | | | |
| ... | | | | | | |

最后产出**两个版本的平均加权分** + **差值**。

---

## 3. 判定准则

| MVP-1 - v1 加权差 | 判定 | 下一步动作 |
|------------------|------|-----------|
| ≥ **+0.5** | ✅ 方向正确 | 立即启动 Phase 1（CLIP + 分段并行 + 末帧链） |
| **+0.3 ~ +0.5** | ⚠️ 部分起效 | 说明 reference + seed 路线接近上限，**这才是上 LoRA 的真正信号**（Phase 2） |
| **< +0.3** | ❌ 方向有问题 | **不要急着上 Phase 1/2**，回到画板。可能原因：v1 已经够好、参考图质量太差、prompt 前缀干扰过强 |

---

## 4. 评分时的关键观察点

特别注意这些**用户视角的"扎眼"瑕疵**，不只看 ArcFace 数字：

- 头发颜色在不同镜头是否改变？
- 服装款式（领口、袖口、纹饰）是否漂移？
- 五官比例（眼距、嘴角弧度）是否变化？
- 镜头切换处的**第一帧**与上一镜的**最后一帧**是否人物特征对得上？
- 同一镜头 5 秒内，是否能看到角色"渐渐变成另一个人"的过程？

> 这些是 ArcFace / CLIP 客观指标看不到、但用户一眼能看出的"灵魂瑕疵"。

## 5. 测试结果归档

把评分汇总写入 `docs/v2-baseline-results-YYYY-MM-DD.md`，包含：

1. 测试时间、评委名单
2. 每条脚本的 v1 / MVP-1 视频 URL（R2 / 本地路径）
3. 评分明细表
4. 加权差值 + 判定结论
5. **关键观察**：哪种镜头 MVP-1 改善最明显？哪种没变化？哪种反而退步？（这是 Phase 1 优化的输入）

## 6. 常见问题

**Q: 没有 3 个评委怎么办？**
A: 自评 + 2 个同事，或 1 人间隔 24h 评 2 次（自我对比也有意义）。最低也要避免"作者自评"——容易过度宽容自己的改动。

**Q: 视频生成太慢，等不及做完整 5 条？**
A: 最少 2 条（单角色 + 多场景切换）。或者优先用旧产出做 v1 基线，只跑 MVP-1 节省时间。

**Q: MVP-1 评分反而比 v1 低怎么办？**
A: 大概率是 identityPrompt 前缀太长或与场景描述冲突。可以临时把 `canonicalPrompt.slice(0, 200)` 改成 `.slice(0, 100)` 再测一轮。

**Q: 怎么知道 referenceImages 真的被用上了？**
A: 看 flow2api 日志：`[flow2api] start { model: "veo_3_1_r2v_*", refsCount: 1+, hasIdentityPrompt: true }` 说明走对了路径。
