2026-11-19 开发分支增强：自动制作计划增加角色参考缺口与模型参考能力警告；既有视觉场记增加道具状态/空间站位检查并复用修复队列；旧编辑器/Workflow/助手视频入口正确处理显式OS/VO口型。详见 [主流程整合说明](seedance-pipeline-integration.md)。该记录表示源码整合，不表示本轮已部署。

已部署至 https://comic.cloudsentryai.com ，当前应用版本为 c3ba27d（2026-11-15 19:27，UTC+8）。Markdown/GFM、联网搜索、当前作品文字操作与项目技能已上线；公网健康、登录保护和新版静态资源核验通过。刷新项目页面后重新打开「AI 助手」即可使用。无新增数据库迁移，既有自动制作继续保留预算确认。

项目列表的系列分组、独立作品卡片和编辑器顶部均提供「AI 助手」入口。回复使用 Markdown/GFM，支持标题、加粗、列表、引用、表格、代码块与来源链接；表格和代码可横向滚动。用户输入保持纯文本，回复禁用原始 HTML 与危险链接，图片不自动加载。

联网搜索与项目工具能力已部署。助手可讨论当前剧情、角色动机、节奏和制作方案，也可按用户的明确要求直接保存作品标题、简介、原文或分镜文字、对白、旁白、情绪、镜头及预估时长。

## 作品关联与记忆

- 同一系列的各集共享一份对话与长期记忆；编辑器入口额外提供当前集资料。
- 独立作品拥有自己的对话与记忆，其他用户无法读取。
- 服务端读取已授权的系列设定、故事圣经、分集概览，以及当前集的原文、角色、剧本和分镜；较长资料会节选并显示提示。
- 聊天成功后自动持久保存，刷新或重新打开可以恢复。界面显示最近40条，模型使用有预算的近期对话。更早记录保存在数据库，当前版本不提供历史分页或语义检索。
- 「剧集记忆」保存用户确认的偏好与决定，最多12000字；已确认记忆完整提供给模型。回答可先「加入记忆草稿」，编辑并点击保存后才生效。模型不会自动把猜测写入记忆或故事圣经。
- 清空聊天需要确认，保留已保存记忆。编辑冲突会保留本地草稿，提示载入最新版本并合并。

## 聊天工具与技能

聊天通过真实的模型工具循环执行工作，工具固定绑定登录用户及当前作品，不能由模型覆盖用户或作品 ID。仅讨论、评价或搜索资料不授权写入。系列总览没有选中当前集时，需从具体集打开助手进行操作。

| 工具                              | 用途                                                                                                                  |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `web_search`                      | 请求 Bing RSS 搜索公开网页，返回最多5条标题、链接、摘要及检索时间，无需另配搜索密钥；外网不可用或返回验证码时明确失败 |
| `list_skills` / `read_skill`      | 发现和读取仓库 `.claude/skills` 与 `.agents/skills` 的 `SKILL.md`，包括叙事、角色一致性、镜头语言、音频及导出技能     |
| `read_project`                    | 按页读取当前作品与真实分镜 ID，每页20镜，文字共用16000字预算并标记截断                                                |
| `update_project` / `update_scene` | 保存用户明确要求的当前作品或分镜字段，严格校验字段白名单与归属                                                        |
| `plan_production`                 | 使用用户给出的积分上限创建既有自动制作计划，复用本轮请求编号去重；不启动付费制作                                      |
| `production_status`               | 读取当前集真实制作进度                                                                                                |

例如：“查一下雨夜悬疑片的镜头参考，附来源”“按项目叙事技能检查开头三秒钩子”“把第1镜对白改成‘谁在门外？’并保存”“预算100积分，为本集创建补图制作计划”。技能仅提供指导，不开放任意主机文件、Shell 或跨作品访问；搜索结果和技能内容不能覆盖系统权限。部署脚本仅同步 `.claude` 下的技能文档，不携带其余开发配置；构建追踪也显式包含技能文件。

工具成功写入后，聊天附真实操作记录，编辑器和项目列表缓存自动失效。若后续模型总结失败，仍保存已完成操作的回执。修改文字不自动重生成现有图像、视频和音频。图片和视频生成继续在「自动制作」页查看预算并确认执行；不自动发布作品。

## 当前集自动制作

在「AI 助手 → 自动制作」中选择当前集、图片/视频模型、积分上限、最多修复轮数（0/1/2）及是否生成视频，点击「查看执行计划」。创建计划只读取项目、配置和价格，不调用付费模型。计划展示真实模型、步骤、基本制作费用与含最大修复轮数的最坏积分费用；费用超过上限、缺少模型或有素材正在生成时会阻止确认。

确认一次后，服务器依次执行：准备场景地点 → 补齐缺失背景参考 → 补齐缺图 → 检查相邻镜连续性 → 对严重问题按镜头合并并有限修复、复查 → 应用合适的首尾帧衔接 → 生成缺失视频。仅处理当前集既有分镜，不重新生成剧本或重建分镜；同项目一次只运行一个制作任务，单集最多100镜。

- 后台进度和每步费用持久保存在数据库，关闭页面不会停止制作；重新打开会恢复。聊天也会获得当前集的真实执行摘要，不会把计划说成已执行。
- 「停止后续步骤」阻止新任务启动，已提交的唯一任务仍可能完成和结算。余额不足可补足后继续同一任务，累计花费与修复轮数保持原值；主动停止后可核对结果并重新计划。
- 计划确认前素材、模型或价格发生变化会要求重新计划；执行中模型价格变化也会暂停。视觉检查不完整、修复次数耗尽，或检查后的画面/设定再变化时停止后续视频，要求检查素材并重新计划。
- 自动图片不隐式生成换装图或重画，自动视频不隐式补尾帧图；应用层不自动重试付费图像请求或切换供应商。上游服务自身的内部行为仍由其控制。
- 上游超时、连接中断、进程重启等使结果无法确认时，任务标为结果未知并暂停，不自动重提。后台仅核对原有任务，明确成功后结算原任务；无法恢复的外部结果需要人工排查，不提供跳过未知结果继续付费的按钮。
- 已有图和视频会跳过；自动修复前保留原图历史。生成期间手动换图/视频/背景不会被晚到结果覆盖，新产物仍保存在版本或任务结果中，并暂停提醒。当前界面主要通过「查看本集结果」进入编辑器检查素材。
- 积分上限仅约束本次任务的站内积分，不保证限制用户配置的外部模型服务商账单。文字判断/视觉检查不扣站内积分，上游仍可能收费。处理中积分是任务预算预留，不冻结账户余额；其他手动任务仍可消费账户，余额不足则暂停。

执行记录复用 `GenerationTask` 持久化计划、租约、检查点及唯一操作凭证，不新增数据库表。15秒扫描仅推进已确认任务，每进程最多同时推进两个项目；同一步始终关联同一操作凭证，重启后不能用重新下单冒充恢复。

| 接口                                        | 行为                                                 |
| ------------------------------------------- | ---------------------------------------------------- |
| `POST /api/assistant/executions`            | `projectId`、UUID `requestId`、`options`；只创建计划 |
| `GET /api/assistant/executions?projectId=…` | 读取当前集最新计划/进度                              |
| `GET /api/assistant/executions/[id]`        | 读取当前用户的指定执行记录                           |
| `POST /api/assistant/executions/[id]`       | UUID `requestId` 与 `action: confirm/resume/stop`    |

执行接口验证当前用户对作品及系列的归属，显式模型配置必须属于本人且已启用。旧图片/视频生成HTTP接口继续使用原鉴权与限流入口，共享内部生成服务，浏览器不能传入内部幂等/预算/CAS控制参数。

## 免费背景音乐

在具体作品/当前集的「对话」中可直接要求：“帮本集加上背景音乐”“把 BGM 音量调到 20%，打开对白闪避”“关闭背景音乐”或“恢复原背景音乐”。助手使用真实内置免费曲库，也可按分镜情绪自动选曲；不要求制作积分预算，不生成参考图、分镜图片或视频。模型服务自身的对话费用仍由上游决定。

- `read_bgm` 读取当前配乐与真实曲库；`configure_bgm` 支持自动选曲、指定曲目、调整、关闭和恢复。仅接受曲库编号与受限混音参数，模型不能传入外部音频地址或切换作品。
- 曲库只列出服务器实际存在且通过大小/MPEG帧检查的 MP3。自动选曲优先匹配情绪，无匹配时选择其他可用曲目；指定曲目缺失或曲库为空则明确报错，不保存失效地址。下载/部署方法见 `app/public/bgm/README.md`；部署在构建前幂等补齐全部曲目，失败停止发布，并保留服务器已有的 MP3。
- 咨询、否定和资料内容不授权修改。已有曲目（包括暂时关闭的用户上传音乐）会保留，只有明确要求换曲才允许替换；调整音量不会重选音乐。
- 设置保存到编辑器和导出共用的 `generationParams.backgroundMusic`。助手提供单曲配乐，选曲时显式关闭自动分段，避免覆盖选定曲目；调整音量/关闭/恢复会保留原有分段设置。配置保存后可在编辑器预览，已导出的视频需重新导出，助手不会声称旧成片已重合成。
- 只加配乐时，服务端会阻止误调用视觉制作计划；预算数字追问沿用最近用户目标，助手自己的建议不能扩大范围。混合的音频与视觉制作要求仍应逐项核对，视觉部分保留计划与确认。

## 物理地点与旧计划

短剧的剧情标题与物理地点是两个字段：例如剧情标题“剑悬颈”“下令”可共用地点“宗门刑台”。新脚本输出独立 `locationKey`；旧脚本缺少地点时保持未标注，不再把标题直接写成地点。

新制作计划会核对能够逐镜追溯到旧脚本的标题标签，先根据画面校准地点，再按实际地点展开参考板。旧地点行、已生成图片与视频均保留。标注不完整、仍返回原剧情标题或期间用户修改分镜时暂停，不能继续批量付费生图。旧版在途计划若仍含此问题，会在后续新步骤前暂停并要求重新计划；已提交任务允许核对收尾，费用记录保留。

## 模型和请求

复用「设置 → AI 模型配置」中的文字模型及现有 OpenAI-compatible、Claude、Gemini 等协议；配置了 GPT 即可选择 GPT。界面自动选择已测试成功的默认文字配置或首个可用配置，首次提问也显式发送该配置，保证显示与实际调用一致。没有可用配置时提供设置入口，并提示先配置及测试。指定配置必须属于当前用户、启用且类别为 LLM，模型必须在该配置已登记清单内；服务端未显式选型时仍保留既有文字辅助的默认配置兜底行为。

与现有文字辅助一致，应用不扣积分，上游仍按自己的规则计费。每轮模型最多2048个输出token，单次提问最多6轮模型调用及12次工具执行，整体75秒超时，不自动重试；工具串行执行。配乐或制作计划保存成功后直接返回确定的操作回执，避免额外模型总结超时；文字编辑仍可继续多步完成。沿用现有限流。所选模型及上游必须支持工具调用（function calling）；OpenAI-compatible、Claude、Gemini 分别使用对应协议。若启用了现有 Langfuse 观测配置，消息与回答按统一观测规则记录。

同一部剧只允许一个活跃回复。请求编号用于网络重试去重；成功的问答成对原子保存，未发生写入时模型失败保留原有聊天和记忆；已写入时返回真实回执，不把模型总结失败误报为保存失败。超时返回明确的504提示，建议先核对作品/任务状态；运行日志只记录请求编号、步骤数、耗时及受限错误类型，不输出供应商异常正文、密钥或作品提示词。关闭界面会中止浏览器等待，服务器已经开始的调用仍可能完成，可稍后重开或刷新聊天查看。数据库租约到期后允许恢复；进程崩溃、上游已接收但尚未落库时无法保证外部调用恰好一次，重新发送可能再次产生上游费用。

## 接口与数据

所有接口需登录，作品范围为 `projectId` 或 `seriesId`，恰好一个。单集的系列归属由服务端解析；不信任客户端传来的作品事实。

| 接口                                                         | 行为                                                             |
| ------------------------------------------------------------ | ---------------------------------------------------------------- |
| `GET /api/assistant?projectId=…` / `?seriesId=…`             | 范围、最近消息、确认记忆版本、忙碌状态                           |
| `POST /api/assistant/messages`                               | `content`、UUID `requestId`、可选 `configId`/`model`，最多4000字 |
| `PATCH /api/assistant/memory`                                | `content`、乐观锁 `version`，最多12000字                         |
| `DELETE /api/assistant/messages?projectId=…` / `?seriesId=…` | 清空聊天，保留记忆                                               |

新增 `AssistantThread`、`AssistantRequest`、`AssistantMessage` 三表。Thread记录唯一作品范围、用户确认记忆及回复租约；Request记录输入指纹和处理状态；Message仅保存成功的问答。删除用户/系列/独立作品时按外键级联清理。记忆更新与清空聊天均拒绝活跃回复期间修改。

## 数据库与上线

增量迁移文件：`app/prisma/migrations/20261114000000_add_project_assistant/migration.sql`。上线时先备份数据库并确认现有迁移基线，再通过当前环境既有迁移流程应用这份增量，生成 Prisma 客户端、构建并更新服务。不要对生产数据库运行测试或 `prisma db push`，不要为此重置迁移历史。

三张新表与现有业务表为增量关系，回退应用构建时可保留这些表和已产生的聊天；不要在回退时自动删除用户记忆。仅源码集成或隔离构建通过不等于已更新线上服务。
