# 项目 AI 助手

已部署至 https://comic.cloudsentryai.com ，当前版本 `508e22b-tts-c1da6dba6a78`（2026-11-15语音兼容更新），24项本机/公网检查通过；助手静态资源与上版保持一致。刷新项目页面即可使用「AI 助手 → 自动制作」。自动制作复用既有数据库表，未新增迁移；基础助手所需迁移已在此前部署完成。

项目列表的系列分组、独立作品卡片和编辑器顶部均提供「AI 助手」入口。可以直接问文字模型通用问题，也可以讨论当前剧情、角色动机、节奏、制作优先级或比较创作方案。

## 作品关联与记忆

- 同一系列的各集共享一份对话与长期记忆；编辑器入口额外提供当前集资料。
- 独立作品拥有自己的对话与记忆，其他用户无法读取。
- 服务端读取已授权的系列设定、故事圣经、分集概览，以及当前集的原文、角色、剧本和分镜；较长资料会节选并显示提示。
- 聊天成功后自动持久保存，刷新或重新打开可以恢复。界面显示最近40条，模型使用有预算的近期对话。更早记录保存在数据库，当前版本不提供历史分页或语义检索。
- 「剧集记忆」保存用户确认的偏好与决定，最多12000字；已确认记忆完整提供给模型。回答可先「加入记忆草稿」，编辑并点击保存后才生效。模型不会自动把猜测写入记忆或故事圣经。
- 清空聊天需要确认，保留已保存记忆。编辑冲突会保留本地草稿，提示载入最新版本并合并。

聊天负责建议与解释；实际操作在「自动制作」页确认后执行。助手关联服务器数据库中的当前用户作品资料，不扫描主机其他文件，也不自动发布作品。

## 当前集自动制作

在「AI 助手 → 自动制作」中选择当前集、图片/视频模型、积分上限、最多修复轮数（0/1/2）及是否生成视频，点击「查看执行计划」。创建计划只读取项目、配置和价格，不调用付费模型。计划展示真实模型、步骤、基本制作费用与含最大修复轮数的最坏积分费用；费用超过上限、缺少模型或有素材正在生成时会阻止确认。

确认一次后，服务器依次执行：准备场景地点 → 补齐缺失背景参考 → 补齐缺图 → 检查相邻镜连续性 → 对严重问题按镜头合并并有限修复、复查 → 应用合适的首尾帧衔接 → 生成缺失视频。仅处理当前集既有分镜，不重新生成剧本或重建分镜；同项目一次只运行一个制作任务，单集最多100镜。

- 后台进度和每步费用持久保存在数据库，关闭页面不会停止制作；重新打开会恢复。聊天也会获得当前集的真实执行摘要，不会把计划说成已执行。
- 「停止后续步骤」阻止新任务启动，已提交的唯一任务仍可能完成和结算。余额不足可补足后继续同一任务，累计花费与修复轮数保持原值；主动停止后可核对结果并重新计划。
- 计划确认前素材、模型或价格发生变化会要求重新计划；执行中模型价格变化也会暂停。视觉检查不完整、修复次数耗尽，或检查后的画面/设定再变化时停止后续视频，要求检查素材并重新计划。
- 自动图片不隐式生成换装图或重画，自动视频不隐式补尾帧图；应用层不自动重试付费图像请求或切换供应商。上游服务自身的内部行为仍由其控制。
- 上游超时、连接中断、进程重启等使结果无法确认时，任务标为结果未知并暂停，不自动重提。后台仅核对原有任务，明确成功后结算原任务；无法恢复的外部结果需要人工排查，不提供跳过未知结果继续付费的按钮。
- 已有图和视频会跳过；自动修复前保留原图历史。生成期间手动换图/视频/背景不会被晚到结果覆盖，新产物仍保存在版本或任务结果中，并暂停提醒。当前界面主要通过「查看本集结果」进入编辑器检查素材。
- 积分上限仅约束本次任务的站内积分，不保证限制用户配置的外部模型服务商账单。文字判断/视觉检查不扣站内积分，上游仍可能收费。处理中积分是任务预算预留，不冻结账户余额；其他手动任务仍可消费账户，余额不足则暂停。

执行记录复用 `GenerationTask` 持久化计划、租约、检查点及唯一操作凭证，不新增数据库表。15秒扫描仅推进已确认任务，每进程最多同时推进两个项目；同一步始终关联同一操作凭证，重启后不能用重新下单冒充恢复。

| 接口                                        | 行为                                                 |
| ------------------------------------------- | ---------------------------------------------------- |
| `POST /api/assistant/executions`            | `projectId`、UUID `requestId`、`options`；只创建计划 |
| `GET /api/assistant/executions?projectId=…` | 读取当前集最新计划/进度                              |
| `GET /api/assistant/executions/[id]`        | 读取当前用户的指定执行记录                           |
| `POST /api/assistant/executions/[id]`       | UUID `requestId` 与 `action: confirm/resume/stop`    |

执行接口验证当前用户对作品及系列的归属，显式模型配置必须属于本人且已启用。旧图片/视频生成HTTP接口继续使用原鉴权与限流入口，共享内部生成服务，浏览器不能传入内部幂等/预算/CAS控制参数。

## 模型和请求

复用「设置 → AI 模型配置」中的文字模型及现有 OpenAI-compatible、Claude、Gemini 等协议；配置了 GPT 即可选择 GPT。界面自动选择已测试成功的默认文字配置或首个可用配置，首次提问也显式发送该配置，保证显示与实际调用一致。没有可用配置时提供设置入口，并提示先配置及测试。指定配置必须属于当前用户、启用且类别为 LLM，模型必须在该配置已登记清单内；服务端未显式选型时仍保留既有文字辅助的默认配置兜底行为。

与现有文字辅助一致，应用不扣积分，上游仍按自己的规则计费。每次回答最多2048个输出token、75秒超时，不自动重试；沿用现有限流。若启用了现有 Langfuse 观测配置，消息与回答按统一 AI 门面的规则进入观测系统。

同一部剧只允许一个活跃回复。请求编号用于网络重试去重；成功的问答成对原子保存，模型失败保留原有聊天和记忆。关闭界面会中止浏览器等待，服务器已经开始的调用仍可能完成，可稍后重开或刷新聊天查看。数据库租约到期后允许恢复；进程崩溃、上游已接收但尚未落库时无法保证外部调用恰好一次，重新发送可能再次产生上游费用。

## 接口与数据

所有接口需登录，作品范围为 `projectId` 或 `seriesId`，恰好一个。单集的系列归属由服务端解析；不信任客户端传来的作品事实。

| 接口                                                         | 行为                                                             |
| ------------------------------------------------------------ | ---------------------------------------------------------------- |
| `GET /api/assistant?projectId=…` / `?seriesId=…`             | 范围、最近消息、确认记忆版本、忙碌状态                           |
| `POST /api/assistant/messages`                               | `content`、UUID `requestId`、可选 `configId`/`model`，最多4000字 |
| `PATCH /api/assistant/memory`                                | `content`、乐观锁 `version`，最多12000字                         |
| `DELETE /api/assistant/messages?projectId=…` / `?seriesId=…` | 清空聊天，保留记忆                                               |

新增 `AssistantThread`、`AssistantRequest`、`AssistantMessage` 三表。Thread记录唯一作品范围、用户确认记忆及回复租约；Request记录输入指纹和处理状态；Message仅保存成功的问答。删除用户/系列/独立作品时按外键级联清理。记忆更新与清空聊天均拒绝活跃回复期间修改。

## 数据库与上线

增量迁移文件：`app/prisma/migrations/20261114000000_add_project_assistant/migration.sql`。上线时先备份数据库并确认现有迁移基线，再通过当前环境既有迁移流程应用这份增量，生成 Prisma 客户端、构建并更新服务。不要对生产数据库运行测试或 `prisma db push`，不要为此重置迁移历史。

三张新表与现有业务表为增量关系，回退应用构建时可保留这些表和已产生的聊天；不要在回退时自动删除用户记忆。仅源码集成或隔离构建通过不等于已更新线上服务。
