# 审片结果与素材版本对应优化

日期：2026-11-13。范围：导出前审片报告中的历史叙事评分与视觉连贯性结果。本轮由并行 review_freshness agent 实现，主 agent 负责最终全套验收及分镜持久化链路修复。

## 问题与结果

原 `review-report` 路由只读取最近一次工作流叙事评审和完成的 AI 场记任务，既没有比较当前分镜文本，也没有比较当前图片。用户修改对白、镜序、时长或替换图片后，旧的高分和 A 级仍可能作为当前作品结论出现。

现通过两个独立输入指纹判断对应关系：

- 叙事指纹：按实际镜序记录景别、描述、情绪、时长、对白、旁白、出场角色、动作与运镜。忽略真实数据库 ID、图片/视频/音轨 URL 和更新时间；单纯出图或配音不会让仍有效的文本评审失效。报告用当前成片速度换算时长，因此改倍速会提示叙事节奏需要重审。
- 视觉指纹：记录实际送评的相邻图片对、分镜 ID/镜序、地点、剧情描述、角色、换装说明及期望色板。音轨等未送评信息不参与指纹。场记启动时即把版本写入任务 input，不在检查完成后重新读取变化后的素材冒充原输入。

指纹使用固定字段 JSON 与 `SHA-256`，带 `sha256:v1:` 版本前缀，不保存额外原始文本副本。叙事指纹存于实际选中版本的 review artifact；视觉指纹存于实际评审任务 input。

## 用户可见行为

| 比较结果 | 报告行为 |
| --- | --- |
| 当前输入一致 | 复用已取得的评分、评级与建议，不额外调用模型 |
| 当前输入不同 | 显示“已过期”，该节为告警，不展示历史通过/旧建议作为现行结论 |
| 历史无指纹或指纹格式非法 | 显示“无法核验”，提示重查，不猜测其仍有效 |
| 没有历史结果 | 保留现有“未评审/尚未运行”分支 |

角色列表按集合规范化；空白字符串、null 与缺省按现有语义归一。当前内容回退到旧评审的原输入后，可重新识别对应关系，不用修改任务历史或靠时间戳猜测。

## 实现范围

- 新增 `lib/review-freshness.ts` 纯逻辑。
- `workflow/steps/review.ts` 为实际选用的分镜结果写入 inputFingerprint；内部 `ReviewArtifactData` 增加可选字段。
- `continuity-check/route.ts` 在建任务时记录本次实际输入版本，并与报告共用色板解析。
- `review-report/route.ts` 在既有归属校验之后读取当前分镜及角色，分别比对两类证据；不写数据库、不启动任务、不触发任何模型调用。
- `lib/review-report.ts` 增加 current/stale/unknown 状态处理；旧纯函数调用可省略该字段，实际 API 会明确比对。

审计额外发现 `runStoryboardStep` 曾只把增强/修订分镜写入 artifact，数据库还停在 Step 1 的原始解析。该断点由主 agent 单独补齐：持久化实际定稿而不重建素材。本轮的版本比对不会用生成图片的 `updatedAt` 掩盖该问题。

## 边界与回退

- 指纹验证输入一致性，不证明 AI 判断准确，也不是观众留存或“爆款概率”。
- 图片指纹基于 URL。假如外部供应商在同一 URL 下替换文件内容，无法仅靠 URL 发现；现有生成素材应使用不可变的独立资源地址。
- 不主动重跑付费评审，历史工作流仍是对应运行的记录；本轮修复的是重新生成审片报告时对当前素材的判定。
- 无数据库迁移、全局配置修改或部署；新增 JSON 字段可向后读取。逐文件撤回即可回退，保留既有素材与历史结果。
