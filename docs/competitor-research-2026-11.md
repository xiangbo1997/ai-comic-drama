# AI 漫剧工作台竞品研究与优化依据

调研日期：2026-11-13（UTC）。本报告由并行竞品研究 agent 编写；代码观察是本轮优化开始时的基线，不代表后续实现状态。

## 决策摘要

建议优先补齐“创作证据 → 审阅 → 单镜修正 → 成片验证”的闭环，而不是继续堆叠“爆款”提示词或引入新的通用画布。

1. 当前项目已有角色参考、场景锚点、系列记忆、分镜表、时间轴、版本、导演评审、视觉场记和剪映导出。竞品列出的很多功能已经存在，应改善发现路径、输入质量和跨步骤状态。
2. 本轮最有价值的差距是：让导演评审真正看到时长、对白和旁白；统一互相拉扯的节奏约束；按工作阶段给出下一步；在高成本生成之前审阅角色与分镜；支持失败续跑与局部修改。
3. “更可能让观众看下去”必须转为可测量的创作假设。官网宣传中的“viral”“转化提升”不是本项目有效性的证据；任何结构评分都不能保证真实播放量。
4. 竞品状态有变化：Dashtoon Studio 官方入口已显示停服公告并引导至 Frameo；Katalist 首页当前强调广告与产品替换。不能沿用旧文章把它们都描述为仍以漫画生产为核心的产品。

## 调研范围与证据边界

本轮读取了 11 个产品/项目的官方公开页面或官方仓库，另记录 2 个未完成验证的候选。没有登录账号、购买套餐或生成同题材样片，因此下列“官方页面列明”属于可核对的公开产品描述，不等于已实测的可靠性、一致性或质量。

采用的证据等级：

- A：官方仓库 README/源文件可读取，能核对接口或工作流描述；本轮未部署运行竞品。
- B：官方公开主页或 FAQ 可读取，能核对公开列出的能力与定位；未验证登录后的体验。
- C：只有页面标题/元描述，正文依赖客户端渲染；仅确认公开定位。
- 未验证：DNS、证书或连接失败，不据此评价产品能力。

抓取时保留 HTTPS 验证，没有通过关闭证书校验读取失败站点。未使用第三方榜单、付费测评或未经核对的“爆款率”。所有 URL 的获取日期均为 2026-11-13；页面与仓库的 main/master 内容可能继续变化。

## 重复与不合理之处的处理原则

### 应整合的数据和规则

- 节奏、镜长、模型能力和成本估计应分别有唯一规则来源；不同页面可以展示同一信息，但不应各自维护不同阈值。
- 人工审阅、AI 文本评审、AI 视觉检查与导出预检应共享概览入口和版本信息，保留各自证据来源。人工点击确认不能替代视觉检查；AI 分数不能替代素材完整性检查。
- 向导、手动生成和全自动管线应共享角色参考就绪、任务状态与失败分类，避免出现“这里可生成，那里又说缺角色”的情况。
- 成片装饰可以从时间轴与顶部菜单进入，只要两者使用同一个持久化配置。这是上下文入口复用；不要仅因按钮重复就删除其中一个。

### 不建议本轮直接扩张的功能

- 不为追平 Toonflow/Kling 新增无限画布：现有分镜、时间轴和弹窗的信息结构尚需打通，另造工作区会增加学习和维护成本。
- 不照搬 Katalist 的广告产品替换和投放流程：这是不同的目标用户和创作目标。
- 不继续加入“所有题材必须打脸、所有相邻镜必须换运镜、任何作品都必须留续集钩子”等绝对规则。短片、独立完结故事与系列剧有不同目标；应保留编辑空间。
- 不将竞品公开案例的费用、播放量、耗时直接当成本项目的承诺。

## 样片验证方案

这一轮的代码改动可验证数据正确性和流程清晰度，作品质量还需要样片与观众反馈。建议保留原版本作为基线，采用以下小样本试验；这些数量是试验设计，不是统计显著性结论。

1. 固定三种故事：都市反转、悬疑追踪、治愈奇幻；每种准备 30 秒和 90 秒两版，覆盖完结短片与系列续集。
2. 固定输入故事、角色参考、供应商型号、生成参数与预算上限；记录所有重试和人工改稿。若模型不支持固定随机种子，记录其不可控因素。
3. 盲评开场理解、人物一致性、因果清晰、情绪变化、对白可读性、音画同步、结尾满足度；另外记录每镜生成失败率、人工修正次数和每分钟成片成本。
4. UX 任务测量从创建到首个可预览版本的时间、找不到入口次数、误触发全量生成次数、失败后恢复步数。
5. 有发布授权与实际流量后，再用平台真实的首屏停留、完播、追集等指标评估叙事策略。标题、封面、受众、分发时间会影响结果，不能把变化全部归因于模型或 prompt。

建议验收门槛先用相对基线：评审引用可核查、失效状态正确、流程无需重建项目恢复、局部修改不触发无关镜头生成。质量和留存提升作为待样片验证的结果记录，不预填提升百分比。

## 本轮已实施的评分修复

本轮已修改 `app/src/services/agents/narrative-observer.ts`：
