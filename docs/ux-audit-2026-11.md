# 漫剧创作体验审计与本轮改进

日期：2026-11-13。范围：项目列表/创建向导、编辑器创作面板、头部、全局进度、分镜列表、批量生成入口及相关请求逻辑。依据是源码与本地自动化验证；未登录生产系统、未执行付费模型调用，也未声称完成浏览器可用性测试。

## 已修复的问题

| 问题与源码证据 | 本轮行为 | 对创作者的价值 |
| --- | --- | --- |
| `editor/[id]/page.tsx` 的 `canExport` 只认图片；实际 `api/projects/[id]/export/route.ts` 按 `videoUrl || imageUrl` 取有效分镜 | 前端与导出端采用相同画面判据，纯视频项目可进入导出 | 避免已有可用作品却被禁用导出 |
| `PipelineProgress.tsx` 只要一镜有图就直接显示“可导出”，而后端会跳过无图无视频的分镜；同时把全部视频放在必经步骤中 | 统计每镜是否有图片或视频；全片画面齐全与部分预览分开显示；部分导出明确将跳过的镜数；视频注明可选 | 防止把缺镜预览误当完整成片，减少无必要的视频生成 |
| 顶部图片“批量生成”在缺图目标为零时转成全量重生成，且“零目标”还可能意味着剩余分镜正在生成，并非已有图片 | 顶部改为“补齐图片 N”，与底部共用目标筛选；没有目标时禁用，不再从补图入口隐式切换成重生成 | 保护已有画面，避免误花成本；已有图片仍可在对应分镜重生成 |
| 顶部、底部和混合模式分别维护过滤逻辑；底部无目标仍可点 | `lib/editor-readiness.ts` 统一完成数、总数、可生成目标；无目标/没有对应 mutation 的按钮禁用并解释原因 | 同一种操作在不同入口语义一致 |
| 配音总数按有文本统计，完成数却包含没有对白/旁白的遗留音轨；空白字符串也进入配音目标 | 复用真实 TTS 请求的 `buildTtsTextPayload` 判定，完成数只计算需要配音的镜，跳过空白文本 | 完成度不再超过总数，避免无效配音请求 |
| “重试失败”图片按钮直接 mutation，绕过其他出图入口共用的定妆锚关口 | 失败批量重试同样先经过 `onBeforeBatchImages` | 避免修复失败镜时又绕过人物一致性准备 |
| 智能混合模式使用浏览器原生 alert/confirm，批量入口及 `SettingsPanel.tsx` 项目策略开关均声明无本次数据支持的“成本约为 1/2～1/3” | 批量入口使用项目 toast/确认弹窗并展示本次实际视频镜数；两处均移除固定节省比例，项目策略提示实际费用按生成任务计费 | 操作体验一致，成本说明能与当前项目对应 |
| 项目列表的常规新建 mutation 没有 `onError` | 新建失败显示可重试反馈 | 网络或服务错误时不再像点击无响应 |

## 复用与取舍

- 保留顶部快捷补图和底部图/视/音批量入口的位置，共用判据，避免在没有使用数据的情况下直接删除熟悉入口。
- 保留后端已有的部分导出能力。提示缺镜，不把全量视频或配音作为导出硬门槛；静态图运镜成片与无声镜头均属合法创作选择。
- 没有引入新的模型、数据库列或收费操作；生成任务、队列和角色定妆实现仍沿用现有链路。
