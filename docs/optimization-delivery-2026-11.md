# AI 漫剧深度优化交付记录

日期：2026-11-13。按用户要求，由三个子 agent 并行研究竞品、内容生成与创作体验，主 agent 集成端到端质量链路并验收。本轮已实际修改代码；竞品公开能力与尚未实施的建议分别记录。

## 研究与产品判断

已读取 11 个相关产品/项目的官方网页或仓库，包括 Toonflow、火宝、即梦、可灵、Frameo、LTX Studio、Boords 等。白日梦仅取得元数据，不能据此评价内部功能；Dashtoon Studio 的官方停服公告已纠正旧定位。报告：[竞品研究](competitor-research-2026-11.md)。

项目已有角色参考、分镜、版本、图像运镜、系列记忆、导演评审、视觉连贯性检查与导出。优先修复现有功能之间的断点，保留有上下文价值的快捷入口，共享底层规则。没有新增无限画布或另一套质量评分页面。

## 已实现的改进

| 范围 | 具体变化 | 预期作用与可验证边界 |
| --- | --- | --- |
| 故事结构 | 示例为合法 JSON；10–600 秒目标自适应节拍；移除固定90秒与开场/结尾各30秒要求；九宫格示范危机开场 | 减少格式错误、时长越界及矛盾指令；不等于已验证模型创意效果 |
| 题材与兑现 | 统一共享节奏规则，按题材提供情绪回报，本集先兑现再引出有因果的新悬念 | 减少所有题材套逆袭模板、反复拖延与廉价断口；需样片人工评测 |
| 口播时长 | 合理小数镜长取整时仍保护对白+旁白下限 | 回归证明2.4秒口播不再被截成2秒；真实声音仍受语速与模型影响 |
| 审片证据 | 工作流透传时长、对白、旁白、动作和运镜；提供累计时间轴及旁白覆盖数；缺字段标未知 | 评审收到自己需要判断的数据；不把缺数据当零值或实测画面 |
| 评分与版本 | 维度须完整、有限且在0–100；服务端重算权重及通过条件；报告建议与被选中的最优分镜版本对应 | 模型伪造总分/通过标记不能绕过门槛；修订退步时不混用末轮建议 |
| 失败降级 | 叙事评审不可用仍保留分镜继续制作，但事件与审片记录显示未完成、不标质量通过 | 流程容错与质量证明分开，避免“零分却通过” |
| 导出与进度 | 纯视频项目可导出；画面按图片或视频统计；部分导出注明跳过镜数；视频标可选 | 前后端导出资格一致，不把缺镜预览误认完整作品 |
| 批量与反馈 | 顶底批量入口共享目标，补缺失并保留已有图；无目标禁用；配音跳空白及无台词旧音轨；失败重试补定妆检查；新建失败有反馈 | 避免误触全量生成、不正确进度和无响应感 |
| 成本说明 | 混合视频使用项目确认框和实际目标镜数，移除两处无依据的固定省钱比例 | 显示可以核对的信息，未新增报价或费用保证 |
| 工程验证 | 类型、测试、lint、格式均排除 macOS `._*` 二进制元数据 | 原有文件保留，避免其被当作源码解析导致验收失败 |

详细证据：[内容审计](story-quality-audit-2026-11.md)、[体验审计](ux-audit-2026-11.md)。最终命令结果见 [.codex/verification.md](../.codex/verification.md)。

## 需要后续讨论与验证的方向

1. 手机端“创作/分镜/预览”切换：当前桌面布局在小屏隐藏部分编辑区，需要完整窄屏交互验证。
2. 制片人向导持久续跑：组件 state 只能支持当前打开期间的重试；刷新恢复需要服务端幂等与任务状态，不能靠本地缓存冒充完成。
3. 质量概览与版本失效：整合人工确认、文本审片、视觉检查、导出预检的状态及各自证据，修改素材后标记哪些报告需重查。
4. 实际样片：用同一故事、角色、模型与预算比较旧版/新版，盲评因果、开场、人物、对白、音画和结尾满足度，记录修正次数与每分钟成本；平台留存、完播及追集需真实分发数据。

本轮没有购买竞品、调用付费生成、变更数据库、部署服务或发布作品。自动测试证明的是数据与流程正确性；生成质量和“爆款”不能由提示词长度或AI自评分保证。

## 回退

所有产品改动为源码与配置补丁，可按文件独立还原，不需要数据迁移。保留用户原有未跟踪文件与素材；不执行仓库级 reset。缺失协议技能、工具边界与人工分析记录在 `.codex/reasoning.md`。
