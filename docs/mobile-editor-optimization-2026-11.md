# 手机端编辑器优化与浏览器验证

日期：2026-11-13。本轮范围为手机端创作、分镜选择和逐镜编辑；保留桌面三栏、上一轮生成/批量改动及已有数据契约。

## 已修复的问题

| 原问题                                                                 | 本轮实现                                                                                  |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 手机端隐藏 ScriptPanel，只有“请在桌面端打开”提示，空白项目无法输入故事 | 新增共享 `EditorWorkspace`，窄屏显示“创作/分镜/编辑”切换；空项目默认创作，有分镜默认列表  |
| SceneEditor 选镜后使用固定30%和320px最小宽度，与列表争抢小屏空间       | 手机端仅显示当前工作区，编辑器占满可用宽度，空态也可访问；md以上保持三栏                  |
| 简单条件卸载面板会丢失剧本草稿或逐镜迭代状态                           | 三块面板持续挂载，仅用响应式CSS控制显示；浏览器验证跨区往返后原始输入和逐镜未提交草稿仍在 |
| 桌面创作区折叠状态会影响手机布局                                       | 折叠条仅在桌面可见，同一个完整创作内容在手机正常展示；切回桌面恢复用户折叠偏好            |
| 选镜或审片“定位”后手机仍停留在原区                                     | 列表、时间轴、导出审片及制片人审阅定位共用选镜回调，进入编辑区；稳定回调保留列表memo收益  |
| 长标题与一行顶栏工具把手机页面撑宽                                     | 标题可截断、顶栏分行、手机隐藏独立积分展示，主要操作保留；320px及375px均验证无横向溢出    |
| 手机时间轴占用过多纵向空间                                             | 窄屏时间轴最多25dvh并可滚动，桌面不限制原高度                                             |

创作区输入框保留最小可用高度并允许外层滚动，避免面板中其他功能把文本输入挤为零高。没有增加第二套移动生成逻辑，仍调用现有角色检查、解析、逐镜操作与导出服务。

## 自动化验证

新增独立 `playwright.components.config.ts` 与 `e2e/components/`。测试服务由已安装 Vitest 的 Vite 提供，挂载真实 `EditorWorkspace`、`ScriptPanel`、`SceneEditor` 和 `EditorHeader`，加载实际 Tailwind/设计系统CSS。只替换 Next Link 的路由宿主、账户菜单/积分的会话依赖，并拦截API为本地模拟数据。

因此这是有浏览器交互及真实CSS的组件集成验收，不是完整登录后编辑器、真实网络落库、模型生成或支付流程E2E。没有注册账号、连接数据库或调用付费模型。

先写2项浏览器用例，在布局组件尚未实现时执行得到2项RED；实现后解决了独立Vite宿主不提供Next Router环境的问题（明确用锚点替身，不伪造导航成功），再加入320px边界用例。

最终三项通过：

1. 375px：创作输入→分镜→选择分镜进入编辑→修改描述→往返两个区，两种草稿都保留，页面宽度保持375px。
2. 320px：长项目名称不会将预览、导出和输入区挤出视口，页面无横向溢出。
3. 桌面折叠偏好为1：手机仍可输入；调整至1440px，手机导航隐藏、桌面折叠条出现，展开后草稿与三栏均保留。

执行命令：

```bash
PLAYWRIGHT_BROWSERS_PATH=/tmp/ai-comic-playwright pnpm exec playwright install chromium
PLAYWRIGHT_BROWSERS_PATH=/tmp/ai-comic-playwright pnpm exec playwright test --config playwright.components.config.ts
```

本机原无测试浏览器，经工具审批下载至上述临时目录，没有更改依赖版本或全局配置。首次执行被现有 `.aws` 沙箱初始化错误阻断，按工具要求升级执行；没有绕过审批。默认 `playwright.config.ts` 排除这组独立组件用例，避免误用依赖数据库的Next服务执行。

三项浏览器用例最终6.4秒通过；两次 `pnpm type-check` 通过；本轮源码及测试定向ESLint、Prettier格式化、`git diff --check` 通过。整个项目的最终测试与构建由主agent汇总到 `.codex/verification.md`。

成功截图保存在 `app/test-results/editor-workspace-窄屏可从创作切换到分镜编辑，切回仍保留未提交草稿/mobile-editor.png`（测试产物，不提交），已目视检查标题、工具、手机导航、预览与编辑内容的可用布局。

## 边界与回退

首轮验收范围为基本创作与逐镜编辑；后续继续优化补充了下节的触屏、长列表与装饰面板验收。真实 iOS/Android 系统键盘及所有设备组合仍需要设备测试，不把桌面 Chromium 的缩短视口模拟称作真实系统软键盘。

本轮没有数据库迁移、API改动或部署。独立撤回手机布局组件、对应页面/样式和测试配置即可回退；不得用全仓重置覆盖其他agent与用户改动。

## 提交前的手机交互补齐

2026-11-13，继续优化要求下，复用 frontend-patterns 与 e2e-testing 技能和既有隔离浏览器宿主。sequential-thinking 仍不可用，按“真实组件→失败复现→局部修复→浏览器重验”的人工步骤执行，回退仅限本节列明的组件与测试文件。

新增 `interaction-fixture.tsx` 挂载真实 SceneList/SceneCard、24镜 TimelineEditor、滤镜/转场/字幕/水印/贴图面板；数据和持久化请求为本地模拟，不调用模型、不连接账号或数据库。Next Image 的图片优化宿主同 Next Link 一样使用最小 DOM 替身，不声称验证 Next 图片代理。

发现并修复：

- 真正的长列表暴露底部三个批量按钮的最小宽度问题：320px页面实际撑到488px。窄容器改用紧凑标签/计数排列，保留三类操作，模型浮层按首/中/末按钮向内定位；列表内部可滚动，不用 body 隐藏横向溢出来掩盖不可达控件。
- 时间轴控制栏允许换行、内容列允许缩小，长片轨道只在内部横向滚动。
- 时间轴镜长手柄原来只有 mouse 事件。改为 pointer 事件并处理取消，触屏可拖动；提供可聚焦 slider 语义和方向键微调，窄屏手柄加宽。
- 时间轴旧30秒上限与生产60秒输入不一致。现在上限统一60秒，52秒口播镜微调到52.1秒不会被误截到30秒。

触屏分镜排序原有 PointerSensor 与 touch-none 手柄已正确工作，未重写。用 Chromium CDP 的真实 touchStart/Move/End 事件验证手柄排序请求，同时普通卡片区域仍可手指滚动。

新增验收共6项，与原3项组成9项：缩短至375×360后创作/逐镜输入可达且草稿保留；320px长列表/时间轴无横溢且滤镜与转场可滚到末镜并保存；触屏排序与普通卡片滚动；触屏调镜长；长口播镜方向键微调；320px字幕、水印与贴图面板主要控件可达、完成可保存。最终9/9通过，用时23.7秒；9个变更源码/宿主/测试文件定向ESLint通过（0错误0警告）、已格式化。全项目类型检查当时只剩并行向导测试的未完成mock类型，由主agent集成后再验收；手机文件没有类型错误。

这些是实际 Chromium 组件交互验收，未覆盖真实设备输入法遮挡/安全区、Safari与Android版本差异，也不代替完整登录页面网络落库E2E。

### 数据库镜序起点的显示修正

最后独立检查发现：手动分镜数据库 `order` 从0起，工作流分镜从1起；一些面板直接显示 `order + 1`，导致工作流首镜显示成第2镜。保留真实数据库order、分镜ID与媒体查找逻辑，仅将时间轴片段/镜长控件/当前镜提示、滤镜标题、转场两端与贴图选项改为有序数组位置显示。逐镜编辑标题由页面已有 `selectedSceneIndex + 1` 显式传入 `sceneNumber`，不改scene对象。

新增1起数据库镜序的真实组件回归，先因找不到“调整镜头1时长”失败；修复后时间轴、滤镜、转场、贴图与逐镜标题均按第1镜展示，定向用例通过。手机组件用例累计10项，另有真实制片人向导的持久恢复组件用例1项；最终完整11/11通过，用时36.7秒。最后6个显示源码与整个e2e组件目录ESLint通过，全项目TypeScript检查通过，最终diff-check通过。

向导验收使用服务端4/5步骤snapshot，验证关闭重开读取草稿列表、模拟分镜网络失败后刷新恢复、仅继续未完成步骤、稳定operationId，以及完成按钮真实点击后的导航意图。375×640完成态按钮曾位于屏外，已由向导agent修为动态视口限高与内部滚动；最新UI冻结后单独复验通过。网络与Next导航仍为隔离宿主替身，不能据此宣称真实服务端落库E2E。
