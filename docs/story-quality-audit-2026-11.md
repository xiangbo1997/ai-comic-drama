另删除了 `episode-structure.ts` 文件头未经来源支持的“平台数据/编剧课/研究蒸馏”断言，标明规则属于需要作品评测验证的创作启发式。

## 复用、删重与规则取舍

- 复用现有共享节奏块，不建立第二套镜长常量或新的内容生成服务；所有已有消费者获得题材适配与本集兑现规则。
- 保留现有五类钩子、角色说话差异、反转伏笔、单集核心反转数量约束和可选镜头字段，避免扩大数据契约与迁移范围。
- 将“相邻两个爽点/爆发不得超过20秒”改为“15–20秒内有改变局势的新信息、选择或行动后果”，避免让悬疑和治愈也机械爆发。此为创作启发式，不能当真实留存阈值。
- 本轮没有删除九宫格功能：九宫格适合故事总览，但不应代替长片全部执行镜头。当前格式示例明确为字段示范，完整9格仍由现有 schema 约束。

## 已识别、由主 agent 集成的评审断点

原 `SceneSummary` 只有景别/情绪/角色/描述，叙事评审却要求判断开场10秒快切、旁白分镜比例、对白和潜台词；缺失时长及对白/旁白时，评审无法看到自己需要判断的证据。主 agent 负责补齐摘要与 workflow 透传、时间线、旁白数量，以及对旧数据“未知”状态的处理，并同步检查本集兑现。该项的最终测试结果见 `.codex/verification.md`。

本轮新增19项行为验证：9项示例输出契约、6项真实生产 schema 集成、4项时长边界。生产 schema 集成只验证格式接入和一次通过，不把字段示例当完整可上映剧本，也不替代故事质量评测。

## 后续应如何判断是否更好

建议使用同一批原创/授权故事输入，覆盖悬疑、爱情、喜剧、治愈、逆袭及10–600秒时长，对旧版与新版做盲评。记录 JSON 一次通过率、口播下限违规数、无因果反转/拖延钩子数、角色台词可辨识度、人工修改次数与生成成本；优先保证可生产与可理解，再比较开场吸引力和本集回报。播放侧需真实发布样本与足够曝光后观察开播/完播/追集指标，不能以提示词篇幅或 LLM 自评分代替。

回退无需数据库迁移：撤回本报告列出的提示词和 `shot-timing.ts` 变更即可；保留新增测试能明确旧行为重新出现的范围。不得用仓库级 reset 覆盖其他 agent 或用户改动。
