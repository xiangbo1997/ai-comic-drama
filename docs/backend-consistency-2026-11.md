# 分镜原子保存与制片人操作去重

日期：2026-11-13。此项接续第二轮交付中已明确的分镜半写入、响应丢失重试和并发建角色缺口；复用 PostgreSQL 事务、事务级 advisory lock 与现有 GenerationTask，不增加数据库字段或迁移。

## 已实现的保证

- 工作流分镜定稿在单个事务中读取旧镜、匹配角色、更新/创建/删除；中间任何一镜失败都会回滚此前的分镜改动。按项目串行场景写入，保留既有 ID、图像、视频和音频。
- 手动重建使用从 0 开始的镜序，工作流从 1 开始。现在按实际镜序位置匹配既有镜并规范化，避免首镜被删除、素材错移到下一镜。未引入按模型临时 ID 匹配媒体的规则。
- 分镜重建的旧镜快照、角色读取和 generationParams 最新值均在同一个事务锁内读取。对字幕位置、贴图、效果、音效及花字的 ID 桥接，即使镜数不变也会持久化。
- 分镜 POST 支持可选稳定 `operationId`，成功重建与完成凭证一次提交。重复提交相同操作、相同输入返回现有分镜和原 ID；同 key 不同输入或分镜已被另一次替换返回 409，不覆盖用户后续编辑。无 operationId 的手动重新生成保持原有行为。
- 显式 `producerProjectId` 的建角色请求在事务内验证项目归属，按当前用户和规范化姓名加锁，优先复用项目已关联角色，其次复用用户角色库，缺失才创建，并在同一事务补关联。普通建角色仍可创建同名角色。
- 历史清理保留 `producer_checkpoint` 与 `producer_scene_apply` 两种持久记录；关联项目删除仍清理其记录。普通过期任务即使缺少 `kind` 或 JSON 值为 null 也继续清理，使用参数化 SQL 与 `COALESCE` 明确处理 PostgreSQL NULL 语义，避免简单 JSON path 的 NOT 条件漏清旧数据。

场景写入共用锁 key `project-scenes:${projectId}`；制片人最终配置合并也使用此锁。数据库凭证只记录 operationId、用户、输入 SHA256 和 sceneId 列表，不复制剧本文本、生成配置或密钥。

## 边界

operationId 必须由一次持久流程稳定提供，若调用方每次换 key，将被视作有意的新操作。凭证对应分镜被用户替换后会返回冲突而不会自动重建。普通用户手动创建同名角色仍被允许，因此幂等只约束显式制片人创建路径，不是全库同名唯一约束。

此处事务不包含远程模型、上传或视频处理。真实媒体内容没有被自动重新生成，付费调用与部署不在此项执行范围。

按项目协议在 sequential-thinking 工具不可用时采用人工分步核验（事务边界 → 锁范围 → 失败重试 → 权限与普通路径兼容）；回退可独立撤回本项四个生产文件与测试补丁，保留其余 agent 改动，不执行仓库级重置。
