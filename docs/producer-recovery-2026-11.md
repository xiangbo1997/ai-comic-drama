# 制片人向导失败恢复与幂等加固

## 第三轮补齐：服务端持久恢复

2026-11-13 接续实现。以下能力替代第二轮“当前向导实例”边界；后文保留第二轮验收历史，不应将其尚未实现列表作为当前状态。

- 新建 `/api/producer-runs` 与单份草稿读写接口，使用现有 `GenerationTask` 保存输入、世界观、项目 ID、已落库脚本、画像、逐角色进度和完成步骤；不更改数据库结构，不在 checkpoint 中保存模型配置、API Key 或会话令牌。返回给浏览器的快照不含租约 token。
- 向导打开时读取当前用户最近20份草稿，显示未完成的“继续制作”。刷新、关闭重开、响应丢失后以服务器状态恢复，不靠 localStorage 伪造完成。浏览器只推进尚未完成步骤，失败可进入已创建项目。
- 创建请求使用稳定 operationId；同一用户同key同输入取回原run，不同输入冲突。项目创建与run更新在同一个数据库事务内；项目创建已成功但响应丢失时再次推进不会重复建项目。
- 90秒租约与20秒续租防止多个标签页同时推进同份草稿；失效持有者不能提交步骤。页面真正断开后最多等待90秒即可在新窗口继续。租约值仅存服务端，客户端持有自己的随机 token，不暴露给恢复列表中的其他窗口。
- 世界观、脚本与每个角色完成后分别保存进度；角色画像也保存，画像服务不可用时记录降级结果。脚本生成仍复用已有任务；角色创建传 `producerProjectId` 使用原子查重与关联，普通手动同名角色创建保留既有语义。
- 分镜使用稳定 `producer-scenes:${runId}` 操作凭证，同key重放不删除重建 sceneId，内容冲突或分镜被用户替换会停止。最终收尾在共享项目事务锁内校验实际分镜凭证，读取并合并当前配置，保留人工确认及并行配置修改。
- 已完成脚本步骤固定原checkpoint，不允许换另一个scriptId而沿用角色/分镜完成位；失效资源会按服务端校验降级恢复，不能把已删除内容当当前完成。
- 通用后台清理排除持久checkpoint与分镜操作凭证，避免恢复凭据按短期生成日志过期。项目删除仍可清理其关联记录。

新增验收证据：checkpoint/API和客户端边界回归、实际五步编排与中断续跑测试；主agent的临时真实PostgreSQL并发集成测试检查JSONB规范化、同时创建、项目重试、租约与归属。真实 `ProducerWizardDialog` Chromium组件验收模拟了服务端持久数据：关闭重开、收尾500失败、reload恢复、跳过前四步、稳定分镜key及375×640完成按钮可点击；网络为mock，不宣称是真数据库登录页E2E。新增编排helper的10项测试通过，定向覆盖语句94.59%、分支81.63%、函数90%、行95.58%，报告位于 `/tmp/producer-workflow-coverage`；不是全项目覆盖率。具体总测试与构建数字由主agent记入最终verification。

边界：未保存成功的同步世界观/外貌起草若进程退出，可能重新起草该步；这不应重复创建已保存项目、角色或分镜。AI脚本后台任务仍依赖既有进程与失败回收机制。没有外部付费调用、生产迁移或部署；输入指纹与幂等保证不能证明生成审美、爆款效果或exactly-once外部模型执行。

## 本轮恢复保证的边界

- **持久层已有保证**：脚本 GenerationTask 和完成脚本保存在服务端；相同制片人请求可重新取回任务，不重复发起同输入的后台生成。完成任务复用只对显式开关生效，不吞掉普通用户主动“再生成”。
- **当前向导打开期间的保证**：角色失败续跑、分镜成功后的收尾重试、并发收尾请求去重。finalizer 内存记录没有写成 localStorage，也不声称跨刷新有效。
- **尚未实现**：刷新后自动恢复完整五步和最初点子、项目创建响应丢失时的幂等、完整跨标签页角色 CREATE 去重、分镜 POST 服务端成功但响应丢失时的精确确认。完整解决需要服务端生产流程 checkpoint 与幂等操作资源，不能只缓存前端步骤名。
- **进行中旧任务**：不会因年龄自动新建同输入任务，避免后台其实还在执行时重复生成。真正失效任务需现有运维机制先标记失败，随后可重试。
- **并发实测边界**：本轮路由测试 mock 了事务/数据库，核对 advisory lock 调用和项目/用户/指纹条件；没有对真实 PostgreSQL 做多连接并发或进程崩溃注入，不能把这部分称作真实数据库压力验证。
- **配置并发编辑**：读取后合并避免已知字段被收尾固定对象覆盖；项目 PATCH 本身仍是整体替换，未引入跨客户端 compare-and-swap，另一个客户端恰在 GET 与 PATCH 之间更新仍存在原有并发窗口。
