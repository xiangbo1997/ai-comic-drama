## 1. 现状诊断（证据驱动）

### 1.1 转化路径全景：注册 → 第一个成品视频

实际链路（从代码反推）：

```
落地页 page.tsx → /login 注册(送100积分) → /projects(空状态)
  → 新建项目(立即跳 /editor/{id}) → 编辑器输入文本
  → 【点"解析分镜" → 后端 getUserLLMConfig() == null → 400 阻断】❌ 死路
```

新用户在**第一步**（文本→分镜）就撞墙，原因见 1.2。

### 1.2 ⚠️ 核心阻断：新用户必须自配 API Key 才能用，但产品零引导

- `script/parse/route.ts:62-67`：第一步剧本解析，`getUserLLMConfig(userId)` 返回 `null` 时直接 `400 { error: "请先在「设置 > AI 模型配置」中配置大语言模型" }`。**此路径无任何平台兜底 key**。
- `lib/ai-config.ts:91-94 / 159-163 / 219-223 / 279-283`：四个 `getUserXConfig` 在用户无配置时**一律返回 `null`**——LLM/图像/视频/TTS 全军覆没。
- 对比 `services/ai/index.ts:127-142`：`chatCompletion` 在**无 config 传入时**才会回退 `process.env.DEEPSEEK_API_KEY`。但 API 路由永远先 `getUserLLMConfig()` 拿到 `null` 后**根本不调用 chatCompletion**（在路由层就 400 返回了），所以这个 env 兜底对真实用户**永不触发**。
- 结论：**注册送的 100 积分（login/page.tsx:295）是空头支票**——用户没有任何 provider key 时，1 积分都花不出去。这是从注册到 aha moment 之间最致命的断点。

### 1.3 ⚠️ 第一步错误信息被前端吞掉，用户陷入"重试"死循环

- 后端给了**可操作**的引导文案（`script/parse/route.ts:65`：去设置页配模型）。
- 但 `ScriptPanel.tsx:99-103` 把所有 `parseError` 统一渲染成 `"解析失败，请重试"`——**丢弃了后端的具体指引**。
- 后果：新用户看到的是"解析失败，请重试" → 反复点重试 → 反复失败 → 流失。后端那句"去配模型"的救命提示**永远到不了用户眼前**。

### 1.4 落地页：纯静态，零转化设计

- `page.tsx:1-92`：纯文字 + emoji。**无任何作品样片/演示视频/截图**——这是"小说→视频"产品，却完全不展示成品长什么样，价值感知为零。
- `page.tsx:16-20`："开始创作"直接 `href="/projects"`，未登录点进去被 `(dashboard)/layout.tsx:21-23` 重定向回 `/login`——**CTA 实际是个弯路**，且用户不知道为何被踢到登录页。
- 7 步流程图（`page.tsx:59-80`）是静态数字圆圈，**反而强化"这产品好复杂/要 7 步"的劝退感**，没有"一键"的轻量印象。
- footer 之外**无社会证明**（无案例数、无用户数、无"XX 已生成 N 条漫剧"）。

### 1.5 注册页：信息完整但缺 OAuth，门槛偏高

- `login/page.tsx:194-286`：仅邮箱+密码。**无微信/Google/手机号一键登录**——国内漫剧创作者主力是移动端，邮箱注册转化率天然偏低。
- 优点：邀请 banner（:146-159）+ 注册权益清单（:289-310）做得不错，送积分有展示。
- "忘记密码？"（:240）是 `href="#"` 死链；"服务条款/隐私政策"（:316-321）也是 `#` 死链——**信任要素是假的**。

### 1.6 空状态：有图标有文案，但全是"死胡同空状态"

- 项目空状态 `projects/page.tsx:132-149`：🎬 + "还没有项目" + "新建项目"按钮。**但点了"新建项目"只创建一个空白"未命名项目"并跳进编辑器**（:27-35, :62），用户面对空白编辑器**仍不知道下一步该粘贴什么、为什么解析会失败**。
- 角色空状态 `characters/page.tsx:368-385`：同样模式，引导到"创建角色"弹窗，但**没解释为什么要先有角色 / 与项目的关系**。
- 全项目**无一处**示例项目、模板、样片、"试一试 Demo"。`prisma/seed.ts` 只 seed AI provider 目录（:16 起），**不为新用户播种任何 demo 项目/角色**。`grep` 全 `src/` 无 `onboarding/welcome/新手/引导/示例项目` 组件。

### 1.7 AI 模型配置页：工程师向，对小白是天书

- `settings/ai-models/page.tsx` + `ConfigDialog.tsx`：要求用户理解 **API 协议（OpenAI兼容/Claude/Gemini/高级协议）、自定义中转节点、Base URL、authType、CHATGPT_TOKEN+代理地址**（ConfigDialog.tsx:434-451）。这套 UI 是给有中转站经验的极客用的。
- 唯一友好点：Gemini 免费 key 引导（ConfigDialog.tsx:334-364）做得好，有"获取免费 API Key"按钮。**但这是 4 大类里唯一一个**——图像/视频/TTS 类无任何"哪里能白嫖/便宜"的引导。
- 这是整个产品**最高的一道墙**：要跑通一条完整漫剧，用户至少要配 LLM + 图像 + 视频 + TTS **四类**各一个 provider，每类都要去外部网站注册、充值、拿 key、回来填表、测试连通——**对非技术用户接近不可能**。

### 1.8 积分页：信息超载，769 行单文件塞 6 大模块

- `credits/page.tsx`（769 行）一页塞：当前积分+定价说明、每日签到日历、邀请好友、积分包、会员订阅、会员权益、FAQ、支付弹窗。**新用户第一次进来认知过载**。
- 矛盾点：积分页卖力推"100积分≈1条漫剧"（:49）等价值，但用户**配不出 key 根本花不掉积分**——卖积分的前提（能生成）还没解决就先卖货。
- `paymentInfo.methods` 可能为空（:707-711 有"暂无可用支付方式"兜底），说明线上支付可能未配——**积分页可能整个不可用**，却是导航四大入口之一（dashboard-shell.tsx:9-14）。

## 3. 具体优化方案（可落地）

### 方案 A（治本 · P0-1/P0-3）：平台托管「免费试用额度」，解耦 key 配置与首次体验

**核心理念**：把"配 key"从**入门必经**降级为**进阶可选**。新用户用平台兜底 key 跑通第一条漫剧（消耗免费积分），尝到甜头后再引导自配 key 降本。这是 Runway/剪映/Pika 的通用打法——**先让用户成功，再让用户付费/配置**。

**改动点**：让 4 个 `getUserXConfig` 在用户无配置时回退到平台 env key（受积分约束）：

```ts
// lib/ai-config.ts — 新增平台兜底
function getPlatformConfig(category: AICategory): AIServiceConfig | null {
  // 仅当平台显式开启免费试用且配了 env key 时返回
  if (process.env.PLATFORM_TRIAL_ENABLED !== "true") return null;
  switch (category) {
    case "LLM":
      return process.env.DEEPSEEK_API_KEY
        ? { apiKey: process.env.DEEPSEEK_API_KEY, baseUrl: "https://api.deepseek.com/v1",
            model: "deepseek-chat", protocol: "openai", authType: "API_KEY" }
        : null;
    case "IMAGE": /* REPLICATE/SILICONFLOW env ... */ return null;
    // VIDEO / TTS 同理
  }
}

export async function getUserLLMConfig(userId: string) {
  const cfg = await /* 现有查询 */;
  if (cfg) return assembleServiceConfig(cfg, ...);
  return getPlatformConfig("LLM");   // ← 兜底
}
```

配合：在 `User` 上加 `trialCreditsUsed` 或复用现有 `credits`，平台 key 调用只允许在试用积分内消费（防滥用）。**S 工作量**（4 函数对称改 + env + 一个开关），但**直接打通 P0-1**。

> 注意：若运营上不愿托管全部 4 类成本，**最低限度也要兜底 LLM**（最便宜，DeepSeek 解析一次几分钱），让用户至少能跑通"文本→分镜→角色→prompt"的前半程，看到 AI 拆解结果就是第一个 aha moment。

### 方案 B（治标兜底 · P0-2）：把后端引导透传到前端

```tsx
// ScriptPanel.tsx:99
{
  parseError && (
    <div className="mt-2 text-center text-sm text-red-400">
      {/* 透传后端 message；含"配置模型"时给跳转按钮 */}
      {parseError.message || "解析失败，请重试"}
      {/needsConfig/.test(parseError.message) && (
        <Link
          href="/settings/ai-models"
          className="text-primary ml-2 underline"
        >
          去配置模型 →
        </Link>
      )}
    </div>
  );
}
```

前提：编辑器 `parseMutation` 的 `mutationFn` 要把后端 `{ error }` 文案抛进 `Error.message`（查 `use-editor-project.ts` 的 fetch 解析）。**S 工作量**。

### 方案 C（P1-1/P1-2）：落地页样片 + 空状态模板/Demo

1. **落地页加成品轮播**：3-6 个真实漫剧片段（gif/视频）+ 一行原文 → 成片对照。`page.tsx` Hero 下方加 `<DemoGallery />`。展示 > 说明。
2. **空状态改成"模板优先"**：`projects/page.tsx` 空状态除"新建空白"外，加 **2-3 个内置模板项目**（如"古风复仇短剧""都市甜宠"），点击=克隆一个预填好文本+示例角色的项目。需要 `seed.ts` 播种模板，或加 `/api/projects/from-template` 端点。让用户**第一次进编辑器就有内容可解析**。
3. **新建即跳编辑器时给空编辑器加引导**：检测项目无文本时，ScriptPanel 顶部显示"粘贴一段小说，或试试示例文本"+ 一个"填入示例"按钮。**M 工作量**。

### 方案 D（P1-3）：降注册门槛 + 补信任要素

- 接入微信/Google OAuth（NextAuth v5 加 provider，`lib/auth.ts`）。**M**。
- "忘记密码"实现或暂时隐藏（别留死链）；"服务条款/隐私政策"补真实页面或外链。**S**。

### 方案 E（P2）：配置页友好化 + 积分页分层

- 每类 provider 卡片加"哪里拿 key / 是否有免费额度"折叠提示，复用 Gemini 那套（`ConfigDialog.tsx:334-364`）扩展到 IMAGE/VIDEO/TTS（如硅基流动送额度、Volcengine TTS 试用）。**S**。
- 积分页拆分：新用户首次进入只显示"当前积分 + 签到 + 怎么用积分"，把"积分包/订阅/邀请"折叠或移二级。**M**。
- 全局加一个 **onboarding 进度条/checklist**（"① 配置或使用免费额度 ② 创建项目 ③ 生成首张图 ④ 导出"），常驻 dashboard 顶部直到完成。**M**。

## 4. 行业标杆对标

| 维度                  | 本项目现状                       | 剪映/CapCut                 | Runway                        | Pika                    |
| --------------------- | -------------------------------- | --------------------------- | ----------------------------- | ----------------------- |
| **首次产出门槛**      | ❌ 必须自配 4 类 API key，无兜底 | ✅ 开箱即用，平台托管算力   | ✅ 注册即可生成（含免费额度） | ✅ Discord/Web 直接生成 |
| **模板/样片**         | ❌ 零模板、零样片、零 demo       | ✅✅ 海量模板是其核心护城河 | ✅ Gallery + 示例 prompt      | ✅ 社区作品流           |
| **空状态引导**        | ⚠️ 有图标文案但是死胡同          | ✅ 模板墙即首页             | ✅ "Start from example"       | ✅ 示例一键复用         |
| **首次成功(aha)路径** | ❌ 第一步即 400                  | ✅ 选模板→改→导出 1 分钟    | ✅ 输入 prompt→出片           | ✅ 一句话出片           |
| **注册方式**          | ⚠️ 仅邮箱密码                    | ✅ 手机/微信/Apple 一键     | ✅ Google/SSO                 | ✅ Discord/Google       |
| **错误引导**          | ❌ "解析失败,请重试"吞引导       | ✅ 明确可操作提示           | ✅ inline 指引                | ✅                      |
| **进度感知**          | ❌ 无                            | ✅ 引导浮层                 | ✅ onboarding tour            | —                       |

**最大差距**：标杆产品的核心信条是 **"零配置、模板先行、先成功后付费"**；本产品却把**最重的 API key 配置**横在所有人入口前，且**用模板=0**。这是从"工具"到"产品"的根本鸿沟——当前形态更像一个面向开发者的 BYOK(Bring Your Own Key) 中台，而非面向创作者的成品工作台。

**可直接借鉴**：① 剪映的"模板墙即首页/空状态"；② Runway 的"免费额度 + Start from example";③ 通用的 onboarding checklist（Notion/Linear 式四步引导）。

## 5. 实施优先级与工作量

| 顺序 | 项                                                             | 解决      | 工作量  | 理由                                               |
| ---- | -------------------------------------------------------------- | --------- | ------- | -------------------------------------------------- |
| 1    | 方案 B：错误透传 + 跳转按钮                                    | P0-2      | **S**   | 半小时止血，立刻让撞墙用户知道出路                 |
| 2    | 方案 A：平台兜底 key（至少 LLM）                               | P0-1/P0-3 | **S~M** | 真正打通"注册→首次成功"，激活率从≈0 起跳。最高 ROI |
| 3    | 方案 C：落地页样片 + 模板空状态 + 空编辑器引导                 | P1-1/P1-2 | **M~L** | 价值感知 + 首次有内容可玩，降跳出                  |
| 4    | 方案 E：onboarding checklist + 配置页免费额度提示 + 积分页分层 | P2-1/2/4  | **M**   | 进度感知 + 降配置墙高度                            |
| 5    | 方案 D：OAuth + 修死链                                         | P1-3      | **M**   | 降注册门槛 + 补信任                                |

**一句话**：当前产品的转化漏斗在**第一步（文本→分镜）就因 API key 强制门槛 100% 断裂**，且错误提示被前端吞掉——这是"工具"而非"产品"的根因。最高优先级是 **方案 A（平台兜底 key，解耦配置与首次体验）+ 方案 B（错误透传）**，让新用户能用送的积分真正跑出第一条漫剧，再谈一切其他优化。
